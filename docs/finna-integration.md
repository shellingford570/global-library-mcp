# Finna統合（b8 Stage 2）

確認日：2026-11-26。調査の詳細は `docs/b8-api-research.md` §1。

## 位置づけ

Finna（https://www.finna.fi/）はフィンランド国立図書館が運営する
**横断検索プラットフォーム**であり、単一の所蔵図書館ではない。
本アダプター（library_id: `finna`）は既定検索には含まれない
**オプトイン**機関である（§12：既定検索に不要な通信を追加しない）。

区別して保持する4要素：

| 要素 | 出所 |
|---|---|
| FinnaレコードID | レコード `id`（例 `helle.687105`）。ドット前がデータソース |
| データソース／提供元 | ID接頭辞＋`institutions` |
| 所蔵機関 | `buildings` 階層の最深レベル（共同体→図書館→分館） |
| 原本（提供元資料） | `provider_links`。構造検証済み引き継ぎ（Stage 3）でのみ到達 |

## 実装（`adapters/finna.py`）

- キーワード検索（`type=AllFields`）、タイトル／著者／主題検索
  （`type=Title|Author|Subject`、`search_typed`）。
- フィルター：出版年（`search_daterange_mv`）、資料言語
  （ISO 639-1へ正規化して `language:` フィルター）、資料種別
  （`format:`）。ページネーション：`limit`／`page`、総件数は
  `search_page` が `resultCount` を返す。
- 資料詳細：`/api/v1/record`。応答レコードの `id` が要求IDと
  完全一致しない場合は同一性を認めずエラーにする。
- 権利正規化：
  - メタデータライセンスは **CC0 1.0** と明示的に分離記録する。
  - 資料の権利はレコード `usageRights`（機関ラベル。深さ接頭辞を除去）。
    空＝表明なし→ `unknown`。ラベルはライセンスではないので
    CC分類を付けない。ワークスペース側では未知扱いで参照のみ保存が既定。
- 提供元リンク：`onlineUrls`／`urls` は**データとして保持するのみで
  サーバーから取得しない**。既知の提供元ホスト
  （digi.kansalliskirjasto.fi 等）に一致するものだけを
  `handoff_candidates` として印付ける。
- ページOCRはFinnaの機能ではないため実装しない。デジタル資料の
  ページ取得は提供元アダプター（Stage 3）の責務。

## 応答形状の防御的処理

2026-11-26の実応答観測2件で、`formats`／`buildings` の要素が
`{value, translated}` オブジェクトの場合と文字列の場合があり、
先頭レコード自体も観測間で異なった（`resultCount` は一致）。
アダプターは両形状を受け付け、不明な形状は推測せず落とす。
フィクスチャテスト（`tests/test_b8_finna.py`）は両形状を固定している。

## 到達性と実地検証状態（正直な記録）

- 開発VM（サーバーネットワーク）から api.finna.fi は
  **Cloudflareボットチェックで403**。curl／プロジェクトHTTP
  クライアント／テキスト取得の3経路で確認。**回避は行っていない**。
- 利用者の通常ブラウザでは、ブラウザ自身のチャレンジ通過後に
  生JSONが表示され、応答形状と `status: "OK"` を確認できた。
- したがって現時点の検証状態は **fixture_verified** であり、
  LibraryService経由の実地検証は未達成。403は非リトライ可能な
  通常エラーとして表面化する（テストで固定）。
- 公開レート制限は確認できなかった（未確認として記録）。

## Research Workspaceとの関係

検索結果・詳細は既存の共通経路（SearchResult／document payload）
に従うため、資料保存・引用・比較・エクスポートは他機関と同様に
扱える。権利が `unknown` の資料は参照のみ保存が既定となり、
原文抜粋は保存されない（Stage 0の信頼モデル）。
