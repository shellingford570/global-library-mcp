# b8 最終レビュー記録（v1.0.0b8 リリース確定ラウンド）

外部レビュー（PR #19、HEAD `b2fe8e5` 時点の実コード確認）で
指摘された問題を、再現→修正→回帰テスト→評価再実行の順で
解消した記録。指摘の多くは「取得できたこと」と「検証できた
こと」の混同、および権利信頼モデルの迂回経路だった。

証拠の種別を区別する：**実地**（実API）／**フィクスチャ**
（固定HTTP応答＋実コード）／**合成**（生成データ）／
**代理評価**（エージェント付与ラベル）／**静的確認**。

## 1. 修正前の再現結果

候補HEADに対し再現スクリプトで次を確認した。

1. Digi：別資料のALTOでも `PHYSICAL_IMG_NR` が一致すれば
   `verified_mapping=True` になった。
2. Digi：ジャンル不明時に `sanomalehti` を landing_url の
   フォールバックに使っていた（「推測しない」と矛盾）。
3. KB：`verified_mapping` がタイトル一致のみで True になった。
4. 引き継ぎ：ジャンル信号が矛盾する Finna レコードからも
   Digi 候補が返り、提供機関識別子の確認がなかった。
5. 権利信頼：`is_server_source("anything")` が True を返し、
   復元DB内の偽造 `reverify` 観測で抜粋保存が許可された。
6. 権利信頼：`restored_claim` 資料の抜粋本文が Markdown
   エクスポートに漏れた。
7. 復元：`quiesce()` が原子的でなく、信頼降格処理が
   ロールバック対象の try の外側にあった。

## 2. 原典検証の厳格化（§3〜§7）

### Digi（`adapters/digi.py`）
- 資料同一性とページ同一性を分離。`verified_mapping` は、
  単一PageのALTOで、fileName に binding id が完全な区切り
  トークンとして含まれ外国 binding トークンが無く、ページ
  信号に矛盾が無く、OAI `kk:checksum` のページ集合が存在
  する場合はその集合に属すること、の全てを要求する。
  `PHYSICAL_IMG_NR` の一致だけでは検証にならない。
- ジャンル：信号が無ければ unknown、矛盾すれば ambiguous。
  どちらも `landing_url=None`（新聞への推測フォールバック
  を削除）。ページ集合はチェックサム集合そのもので、
  最大ページ番号からの連番推定をしない。文書内検索は
  確認済みページ集合のみを対象とし範囲を明示する。
- `verify_original()` は到達性・形式・対応・目視を分離した。
  画像が正常なJPEGでも別資料のものなら verified にならない。

### KB / Delpher（`adapters/kb.py`）
- OCRペイロードに記事識別子が存在しないため、タイトル対応
  以上の同一性は証明できない。`verified_mapping` は**常時
  false** とし、記事URN／号URN／ページURN（未確認）／
  デジタルページID／OCR単位（article）を分離して保持する。
- 実地取得した711字は「記事OCR取得成功＋タイトル対応」と
  再分類した（厳密な記事同一性・物理ページ同一性ではない）。
  KBのページは検証済み根拠・原典付き引用に入らない。
- `verify_original()` は到達性と同一性を分離し、常時
  unverified を返す（`:image` は実地404）。
- CQL：利用者クエリは単一引用符リテラルとして構築
  （エスケープ＋制御文字拒否）。URNは `re.fullmatch` と
  構造的クエリ解析で検証し、重複urn・資格情報・異常
  ポート・末尾改行を拒否する。

### 提供元引き継ぎ（`handoff.py`）
- Finna→Digi：構造化されたNLF提供機関証拠（`data_source`
  等）を必須とし、無ければ候補表示のみ
  （`candidate_provider_unverified`）。同一 binding への
  ジャンル矛盾は拒否（`refused_ambiguous`）。
- Japan Search→NDL：候補抽出と同一性確認を分離し、候補は
  `identity_confirmed: False` を明示する。

## 3. 権利信頼モデル（§8〜§15）

- 信頼できる観測源を閉集合
  `{"live_fetch","reverify","document_save","page_fetch"}`
  に限定。任意の source 文字列では信頼を確立できない。
  未来時刻の観測・未知の信頼状態は fail-closed。
- スキーマ v4：`rights_observations.trust` 列を追加。
  復元時は**全件**の過去観測を `restored_claim` に降格
  （元の source は履歴として保持）。復元後に新たに実行
  されたサーバー側検証だけが保存許可拡大の根拠になる。
- 共通権利判定：保存・表示・ローカル検索・Markdown・
  JSON・比較の全経路が `trusted_decision()` を使う。
  Markdown は信頼対応済み判定を受け取るよう変更し、
  ローカル検索は差し止め対象引用の本文ヒット自体を
  返さない。申告（claim）は制限方向にのみ作用し、制限の
  解除は信頼できる新しい観測だけが行う。
- b7→b8移行：引用の無いインポート資料・比較のみの資料も
  対象に降格を広げ、v3未満（b7）のDBは由来を証明できない
  ため全資料を `imported_claim` とする（資料・ノート・
  原典参照は保持。再検証で表示は回復する）。
- 引用再検証：資料同一性（library_id／record_id）の再確認、
  ページ同一性、**現在の**権利確認を必須化（過去の申告への
  フォールバックを削除）、2,000字上限を再適用。ハッシュ
  一致は保存許可を証明しない。
- NC系：利用目的確認は利用者の申告であり法的適法性の
  独立検証ではないことを判定理由に明記。未確認では共通
  ポリシーで保存・再保存を止める。
- 権利URI：共有モジュール `rights_uri.py` で正確なホスト
  （creativecommons.org／rightsstatements.org）＋パス文法
  ＋版数を要求。偽装ホスト・埋め込みURI・資格情報を拒否。
  Japan Search／DPLAの表示分類も同モジュールに委譲した
  （保存許可判断には使わない）。
- DPLA：エラー経路でも API キーを除去して表面化する。
  資料IDはパス・クエリ構造を変えられない形に検証する。
  キーは発行しておらず、認証通信も行っていない。
- SQLiteバックアップは保存済み研究データ自体を含む
  機密性の高いファイルであることを復元応答に明記した。

## 4. SQLite復元の安全性（§12）

- `acquire_restore()` で復元開始の所有権を原子的に確保し、
  同時復元は 409 で拒否する。
- 復元は単一の管理操作：検証→quiesce→回復用バックアップ
  （一意名）→置換→起動・移行→**信頼降格（ロールバック
  範囲内）**→整合性検査→疎通確認。置換後のあらゆる失敗で
  元DBへ自動復帰する。ロールバックコピーも一意名・0600・
  後始末付き。

## 5. CIの固定フィクスチャ化（§18）

- `http.FixtureTransport` と `GLM_UPSTREAM_FIXTURE_DIR` を
  追加：上流のみ固定フィクスチャ、実サーバー・実
  WorkspaceApi・実LibraryService・実アダプター・実
  BudgetedTransport・実SQLiteで必須ジャーニーを実行する。
- ワークスペース Playwright 必須6ジャーニーは上流理由の
  skip を廃止。CIは `passed == 6 かつ skipped == 0` を
  検証する。旧ライブ依存スペックは `workspace-live.spec.js`
  に分離し、情報提供のみの別ジョブ（continue-on-error）。
- ローカルでも同一構成で 6 passed / 0 skipped を確認した。

## 6. 多言語展開（§19）

- 主概念に全言語を保証する配分案を実装して評価したが、
  b8固定セットでは改善（Standard Recall@10 0.75→0.8583）
  する一方、b6固定シミュレーションが悪化
  （0.8819→0.8542）したため、§19の規定により**採用しない**。
- 代わりに、選択されなかった言語と上限到達理由を展開計画
  に明示する（`languages_not_represented`／`cap_reason`）。
  上限は無条件に上げていない。3概念以上での sv/nl 飢餓は
  残存課題として残る。

## 9. 機関能力の再集計（§21）

厳密基準での再集計：登録31機関／実装アダプター13。
書誌検索の実地検証済は5（LoC・NDL・IA・KB・Japan Search）、
フィクスチャ1（Finna）、認証待ち1（DPLA）。ページOCRの
実地検証済は **5→4**（KBが記事OCR取得＋タイトル対応に
降格）。ページ対応の実地確認済も **5→4**。原本画像の
実地確認済は4（不変）。Finna／Digi はフィクスチャ検証済・
実API未検証、DPLA は authentication_required のまま表示。

## 10. 既存b7データへの影響

- スキーマ v4 へ自動移行（移行前バックアップ取得）。

  再検証まで差し止められる。資料・引用・ノート・原典
  参照は削除されない。
