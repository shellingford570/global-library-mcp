# b7 workspace performance evaluation

Synthetic data only (no upstream access), generated by
`eval/b7_perf.py`; full numbers in
`eval/results-b7-perf.json`. Environment: this project's
Linux VM (1.5 shared vCPU, ~6 GB RAM), Python 3.12,
medians of 3 runs (1 for import).

Scales: small = 1 project / 100 documents / 300 citations /
100 notes; medium = 5 / 1,000 / 3,000 / 1,000; large =
20 / 10,000 / 30,000 / 10,000.

| measure | small | medium | large | provisional target (brief §38) |
|---|---|---|---:|---:|
| project list | ~1 ms | 1.0 ms | 16.7 ms | < 200 ms |
| save document | ~0.4 ms | 0.36 ms | 1.2 ms | < 300 ms |
| save note | ~0.3 ms | 0.26 ms | 1.0 ms | < 300 ms |
| local search | ~1 ms | 0.8 ms | 6.3 ms | < 1 s (medium) |
| local search (CJK term) | ~2 ms | 2.1 ms | 8.0 ms | — |
| BibTeX export (1,000 docs) | ~20 ms | 20 ms | 28 ms | < 5 s |
| JSON project export | 13 ms | 31 ms | 123 ms | — |
| JSON import (round trip) | 18 ms | 48 ms | 258 ms | — |
| backup | 1.5 ms | 9.8 ms | 80 ms | — |
| DB file size | ~0.2 MB | 2.25 MB | 21.8 MB | — |

All provisional targets are met at every scale on this
modest VM. These are measurements on one environment, not
guarantees for all environments. Upstream-dependent
operations (search, re-verification, comparison fetching)
are excluded — they are bounded by the existing HTTP
budget machinery, not by the workspace store.
Concurrency: the store serialises writes through one
locked connection; a 12-thread concurrent-save test passes
with no errors (tests/test_b7_workspace.py).

## Final review re-measurement (2026-11-26)

Re-measured with the extended `eval/b7_perf.py`
(`eval/results-b7-perf-final.json`): record counts,
excerpt sizes, DB+WAL+SHM disk usage, RSS, cold vs warm
search, concurrent writes/exports, and a measured
store-level restore (validate + swap + reopen). Large
scale (20 projects / 10,000 documents / 30,000 citations /
10,000 notes): DB 23,027,712 bytes, WAL 4,169,472 bytes,
local search 6.41 ms warm / 10.52 ms cold, backup 89.6 ms,
restore 337.2 ms, max RSS 154,720 KB. `synchronous = FULL`
is now in effect; write costs remain ~1-2 ms. Details:
`docs/b7-final-review.md` §5.
