# b8 性能測定（§24）

フィクスチャ環境（ネットワーク遅延なし）で、実アダプター＋
実サービスのHTTP試行を本番の予算コードで数えたもの。時間は
コード経路の比較であり、上流の速度ではない。
実行：`eval/b8_perf.py`、結果：`eval/results-b8-perf.json`。

## 構成A：b7既定機関のみ（loc／ndl／gallica／internet-archive）

- 3クエリ合計の試行：12（各ホスト3）。
- **新規機関ホストへの試行：0**。既定検索に新規機関追加による
  不必要な通信が発生しないことを確認（§12／§24の主眼）。
- 経過時間6.0秒はLoCアダプターの3秒間隔ペーシング（3クエリ分）
  が支配的で、フィクスチャでも実ポリシーどおり作用した。

## 構成B：b8新規機関を明示選択（finna／kb-delpher／japan-search／dpla）

- 3クエリ合計の試行：9（finna 3、KB SRU 3、Japan Search 3）。
- DPLAはキー未設定のため **HTTP試行0** で
  `authentication_required` エラーとして返る（他機関の結果は
  正常に返却：合計8件）。
- 受信量：finna 1,479 B、KB 1,274 B、Japan Search 303 B
  （フィクスチャ応答の実バイト数）。

## 構成C：言語ルーティング（research Standard、languages=[fi, sv, nl]）

- 2クエリ＋再実行1回で試行54（各ホスト18）。クエリ毎の
  HTTPリクエスト数・受信量・実行バリアント数は結果JSONに記録。
- 温キャッシュ再実行では書誌キャッシュが11件ヒットし、
  同一クエリの再検索を吸収した。
- 部分失敗：なし（フィクスチャ範囲）。根拠採用数は本測定の
  対象外（フィクスチャ資料は証拠段まで進めていない）。

## 解釈

- 新規機関はすべてオプトインで、既定検索の試行数は b7 から
  増えていない。HTTP予算は増やしていない（§12）。
- 言語ルーティング時の試行増は展開バリアントの実行による
  もので、上限（モード別バリアント上限とHTTP予算）の内側に
  収まっている。
